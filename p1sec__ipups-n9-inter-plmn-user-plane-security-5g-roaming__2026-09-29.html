英文原标题：IPUPS and N9 security: protecting the inter-PLMN user plane in 5G roaming

IPUPS, inter-PLMN user plane security, is a function of the 5G user plane function that sits at the border of an operator network and polices GTP-U traffic arriving on N9 from a roaming partner. It forwards packets that belong to an active PDU session and discards the rest, it drops malformed GTP-U, and in inter-PLMN deployments the traffic it terminates is expected to be confidentiality, integrity and replay protected. In short, it is the user plane counterpart to what the SEPP does for the control plane, and it was introduced in 3GPP Release 16 to close a gap that 4G roaming had always left to bolt-on equipment. Most published work on 5G roaming security stops at the control plane. The SEPP , the N32 interface and the choice between PRINS and TLS get the attention, because that is where subscriber identifiers, authentication vectors and policy decisions travel. The user plane crosses exactly the same operator boundary, carries several orders of magnitude more bytes, and in a home routed session terminates on an anchor that sits deep inside the home network. This article covers what IPUPS does, where it sits, how it differs from the control plane protections around it, and what a security assessment should establish about an operator's N9 border. What IPUPS is IPUPS is not a separate network function with its own service-based interface. It is a functionality that a UPF can support, described in 3GPP TS 23.501 among the user plane management clauses, and its security requirements are set out in 3GPP TS 33.501. A UPF supporting IPUPS terminates the GTP-U tunnels of the N9 inter-PLMN reference point, which means it is a real tunnel endpoint rather than a transparent middlebox. That distinction matters: because it terminates rather than observes, it can enforce, and because it enforces, a packet that fails its checks never reaches the network functions behind it. The function is controlled through the normal 5G split between control and user plane. In the visited network the IPUPS-capable UPF is controlled by the V-SMF, and in the home network by the H-SMF, each over its own N4 interface using PFCP. That is how the function knows which PDU sessions are active and which tunnel endpoint identifiers are legitimate at any moment: the session state is pushed to it by the SMF that owns the session, not inferred from the traffic itself. The deployment intent in the specification is explicit. Operators may place UPFs supporting IPUPS at the border of their network so that invalid inter-PLMN N9 traffic is rejected before it reaches the rest of the user plane. The word to notice is "may". IPUPS is a standardised capability, not a mandated deployment, and that gap between what the specification defines and what an operator has actually rolled out is the single most useful thing to establish when reviewing a network.
