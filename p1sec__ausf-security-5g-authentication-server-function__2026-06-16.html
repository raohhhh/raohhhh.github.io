英文原标题：AUSF security in 5G: protecting the Authentication Server Function

AUSF security matters because the Authentication Server Function is where the home network decides whether a subscriber is real. In the 5G core, the AUSF is the authentication anchor that sits in the home network and confirms every primary authentication. If an attacker can weaken, bypass, or abuse the AUSF, they undermine the trust the entire network places in subscriber identity. Yet the AUSF receives far less security attention than the AMF or the radio. What is the AUSF and what does it do? The Authentication Server Function is defined across 3GPP TS 23.501 for architecture, TS 33.501 for security, and TS 29.509 for its service-based interface, Nausf. It lives in the home network (HPLMN) and is responsible for primary authentication of the subscriber using 5G-AKA or EAP-AKA prime. In the authentication flow, the Security Anchor Function (SEAF), hosted in the AMF in the serving network, sends an authentication request to the AUSF. The AUSF obtains authentication material from the UDM and its ARPF, which hold the long-term credentials, runs the authentication exchange, and on success derives the anchor key KSEAF that seeds the rest of the 5G key hierarchy. The AUSF also records the authentication result, which is the basis for the home-control feature. Why the home network anchor matters The AUSF gives the home network a say in authentication even when the subscriber is roaming. Through home control, the AUSF stores confirmation that authentication actually happened, so the home network can detect a visited network that falsely claims a subscriber is present and authenticated. That makes the AUSF a control point against a class of roaming and location fraud, and therefore a target. Why is the AUSF a security concern? The AUSF concentrates two sensitive things: it is on the authentication path for every subscriber, and it handles key material at the top of the 5G key hierarchy. Three exposures follow from that. Service-based interface exposure The AUSF is reached over Nausf, a service-based interface using HTTP/2 inside the 5G core service-based architecture. Every weakness that affects the SBA affects the AUSF: missing or weak mutual TLS, OAuth2 access tokens that are not validated or are over-scoped, and NRF registration or discovery that can be poisoned to redirect AUSF lookups. A compromised or rogue network function that can reach Nausf without proper authorization is talking directly to the authentication anchor. Key material and the 5G key hierarchy The AUSF derives KSEAF and handles KAUSF. These keys anchor the confidentiality and integrity protection that follow. Weak transport protection, key exposure, or a downgrade in the authentication method weakens everything derived below. Protecting AUSF key handling is protecting the root of the hierarchy.
