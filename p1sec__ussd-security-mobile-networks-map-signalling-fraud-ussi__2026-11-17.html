英文原标题：USSD security in mobile networks: MAP signalling, fraud risks and how to protect it

USSD security is the protection of Unstructured Supplementary Service Data, the session-based text channel behind balance checks, top-ups, call forwarding codes and, in many markets, mobile money. USSD looks like a handset feature, but its security lives almost entirely in the mobile core: USSD dialogues are carried over MAP on SS7 or SIGTRAN between the visited MSC/VLR, the HLR and a USSD gateway, and they inherit every trust assumption of the SS7 signalling network . Radio encryption protects the first hop only; from the base station onwards a USSD string, including any PIN a subscriber types into a menu, crosses the core in clear text. That combination makes USSD an under-examined attack surface. It is old enough to be treated as legacy, yet it still carries financial transactions, account management and service provisioning for hundreds of millions of subscribers, and the MAP operations that transport it can be sent from the interconnect if an operator's signalling filtering is incomplete. This article explains how USSD works at the protocol level, where the real weaknesses sit, how USSD has been carried into LTE and IMS, and what operators can do to filter, monitor and test it properly. What USSD is and how it differs from SMS USSD is a real-time, session-oriented supplementary service defined by 3GPP for GSM and UMTS. Unlike SMS, which is store and forward, a USSD exchange is an open dialogue between the handset and an application in the network, and the dialogue stays alive until either side releases it or a timer expires. The service is specified in three stages: 3GPP TS 22.090 for the service description, TS 23.090 for the stage 2 procedures and TS 24.090 for the stage 3 signalling on the radio interface. Because the session is interactive, USSD is a natural fit for menus: the subscriber dials a star and hash code, the network returns a menu, and the exchange continues for several rounds. There is no storage on the handset and no delivery report, and it works on any handset without a data connection, which is why operators and service providers still rely on it. From a security point of view, the important difference with SMS is where the logic lives. An SMS is a payload delivered to a device. A USSD dialogue is a command channel into an application server that can query balances, move credit, change forwarding settings or confirm payments. The value of a forged or intercepted USSD exchange is therefore closer to that of a forged API call than to that of a spoofed text message. Operators who already treat SMS-based attacks as a fraud vector should look at USSD with at least the same level of attention. How USSD travels through the mobile core USSD is carried end to end by the Mobile Application Part, defined in 3GPP TS 29.002, running over TCAP and SCCP on classic SS7 or over M3UA on SIGTRAN .
