英文原标题：SCTP security in mobile networks: hardening the transport under SIGTRAN, Diameter and 5G N2

SCTP is the transport almost nobody audits and almost every mobile network depends on. It carries M3UA and M2PA in SIGTRAN deployments, it carries Diameter between LTE, IMS and policy nodes, and it carries NGAP on the N2 interface between the gNB and the AMF. When an SCTP endpoint is reachable from somewhere it should not be, when an association can be torn down by a third party, or when a stack above it mishandles a malformed chunk, the consequence is not a slow web page. It is a signalling outage, a base station that loses its link to the core, or a Diameter peer that stops answering. The direct answer for anyone auditing this layer: SCTP is a well designed transport with genuine anti-spoofing properties, and the majority of SCTP related incidents in mobile networks are not failures of the protocol design. They are failures of reachability control, of cryptographic protection that is specified but left disabled, and of implementation robustness in the protocol stacks sitting on top. This article covers what SCTP provides, where exposure actually begins, which attack classes are realistic against production networks, what 3GPP and the IETF require, and what a defensible hardening baseline looks like. What SCTP is and why mobile networks depend on it SCTP is a reliable, message oriented transport protocol standardised by the IETF, currently specified in RFC 9260, which was published in June 2022 and obsoletes the earlier RFC 4960. It sits alongside TCP and UDP at the transport layer but differs from both in ways that matter for telecom. It preserves message boundaries rather than presenting a byte stream, it supports multiple independent streams within a single association so that loss in one stream does not block delivery in another, and it supports multi-homing, meaning a single association can span several IP addresses on each endpoint. Those three properties are exactly why telecom standards bodies chose it. Signalling is message oriented by nature: a MAP operation, a Diameter request or an NGAP procedure is a discrete unit, not a stream of bytes. It is also loss intolerant, so head of line blocking across unrelated transactions is unacceptable, and signalling nodes are expected to survive the loss of a network path without dropping thousands of sessions. The result is that SCTP now sits under a remarkably broad set of interfaces. In SIGTRAN, M3UA as defined in RFC 4666 carries MTP3 user traffic over SCTP, and M2PA carries MTP2 peer to peer traffic, which is how legacy SS7 reaches IP transport at all. Diameter, specified in RFC 6733, supports both TCP and SCTP, and many operators run SCTP for the Diameter interfaces that matter most. In the radio to core control plane, S1AP is carried over SCTP as specified in 3GPP TS 36.412, and NGAP is carried over SCTP as specified in TS 38.412.
