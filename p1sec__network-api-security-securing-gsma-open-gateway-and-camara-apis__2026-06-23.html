英文原标题：Network API security: securing GSMA Open Gateway and CAMARA APIs

Network API security is the discipline of protecting the standardised interfaces that let external applications use mobile network capabilities such as SIM swap detection, number verification, and device location. With the GSMA Open Gateway initiative and the CAMARA project now exposing these capabilities across hundreds of networks, the mobile core has gained a new, internet facing edge that needs the same rigour operators apply to signalling and the service based architecture. This article explains what GSMA Open Gateway and CAMARA are, how their security model works, where the exposure creates risk, and the controls operators should put in place before opening an API to the public internet. What are network APIs, GSMA Open Gateway, and CAMARA? Network APIs are programmable interfaces that expose specific mobile network functions to third party developers without giving them access to the core itself. GSMA Open Gateway is the industry initiative that defines a common set of these APIs so a developer can integrate once and reach many operators. CAMARA is the open source project, hosted by the Linux Foundation and run jointly with the GSMA, that produces the technical API specifications. The scale is now significant. The GSMA reports that Open Gateway spans more than 80 operator groups, representing roughly 292 networks and over 80 percent of mobile connections worldwide. The CAMARA Fall25 meta release brought the catalogue to around 60 APIs, of which 10 are marked stable. Widely deployed examples include the SIM Swap API, which reports whether the SIM bound to a number changed recently, the Number Verification API, which confirms that the number a device presents matches the number seen on the network, and one time password and device location services. For background on the core that sits behind these interfaces, see our explainers on the mobile core network and mobile network protocols . How the network API security model works Network API security rests on standardised authorisation, explicit subscriber consent, and a 3GPP exposure layer that mediates every request. Each layer matters, because an API that returns whether a given subscriber recently swapped their SIM is handling sensitive data about a real person. Three legged authorisation and subscriber consent CAMARA secures access using OpenID Connect and OAuth 2.0 rather than static keys. Four flows are defined: the OpenID Connect authorisation code flow, the Client Initiated Backchannel Authentication flow known as CIBA, the OAuth 2.0 client credentials flow, and the OAuth 2.0 JWT bearer flow. APIs that act on a specific subscriber require a three legged access token, which involves three parties: the resource owner who is the subscriber, the authorisation server operated by the operator or aggregator, and the client application requesting access.
