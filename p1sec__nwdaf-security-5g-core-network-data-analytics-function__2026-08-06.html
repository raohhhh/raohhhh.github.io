英文原标题：NWDAF security in the 5G core: securing the function that sees the whole network

NWDAF, the Network Data Analytics Function defined in 3GPP TS 23.288, is the 5G core network function that collects data from other network functions and from OAM, derives analytics from it, and offers those analytics to consumers over the service based interface. It is also, and this is the part that rarely appears in architecture diagrams, the function with the broadest legitimate read access in the entire core. Securing it is not a variation on securing any other network function, because the thing that makes NWDAF useful, breadth of visibility across subscribers, sessions, slices and radio conditions, is the same property that makes it valuable to an attacker. This deep dive follows our existing series on individual 5G core functions, and NWDAF is arguably the most under-examined of them. The security model has three distinct dimensions: the confidentiality of the data NWDAF aggregates, the integrity of the analytics and models it produces, and the trustworthiness of the automation that consumes its output. Each of those has a different failure mode. Get the first wrong and you have built a subscriber intelligence repository with weaker controls than the subscriber database. Get the second wrong and you have a function that can be steered into producing wrong answers. Get the third wrong and wrong answers turn into wrong network configuration. What NWDAF does and why it changes the core threat model NWDAF turns raw operational data into named analytics that other functions can subscribe to, and the shift it introduces is that a single function now holds correlated data about subscribers and network state that was previously scattered across many. TS 23.288 defines the framework, and TS 29.520 defines the service API. The analytics themselves are standardised as Analytics IDs, and reading the list is the fastest way to understand the exposure. They include UE mobility, UE communication behaviour, abnormal UE behaviour, network function load, network performance, service experience, user data congestion and QoS sustainability, among others. Some are aggregate and statistical. Others are explicitly per-subscriber: UE mobility analytics describe where a given device tends to be and when, and abnormal behaviour analytics describe deviations from a learned per-device pattern. Those are, in plain terms, movement profiles and behavioural profiles for identified subscribers, produced and stored inside the core. Consumers of these analytics are ordinary network functions. The PCF can use analytics to adjust policy, the SMF and AMF can adjust session and mobility behaviour, and the OAM layer can use them for planning and automation. Analytics can also be exposed outside the operator through the Network Exposure Function to application functions, which turns an internal analytics capability into an externally reachable data product.
