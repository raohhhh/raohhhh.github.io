文章背景与概述： 本文深入分析了5G核心网中统一数据存储库（UDR）的安全问题。UDR作为5G核心网的关键网元，负责存储订阅数据、策略数据、暴露数据和应用数据。由于其存储了决定用户身份和权限的核心数据，UDR成为5G核心网中价值最高的攻击目标之一，但在架构讨论中常被忽视。 攻击原理与安全风险分析： 文章指出，针对UDR的安全风险主要源于标准架构与实际部署之间的偏差，而非协议本身的根本性缺陷。攻击者通常利用以下原理和途径实施攻击： 1. Nudr接口授权粒度不足：标准要求UDR针对每种数据集和每个消费者进行严格授权，但实际部署中常出现粗粒度授权，导致已认证的网络功能（如PCF或NEF）越权访问或篡改不应触碰的数据集（如认证订阅数据）。 2. 非标准接口暴露：攻击者常绕过受SBA安全机制（如mTLS和OAuth 2.0）保护的Nudr接口，转而攻击缺乏充分审查的外部接口。例如：利用配置网关（SOAP/REST/LDAP）的过度特权账户进行大规模数据篡改；利用遗留的4G HLR/HSS前端LDAP访问（Ud接口）绕过5G安全控制。 3. 网络扁平化与隔离不足：如果UDR可被不必要的网段访问，攻击者可通过攻破其他不相关的网络功能作为跳板，横向移动至UDR获取订阅数据。 4. NEF暴露路径的数据完整性攻击：外部应用功能（AF）可通过NEF向UDR写入应用数据（如流量影响请求）。如果NEF对外部实体认证不严或数据校验不足，攻击者可注入恶意数据并持久化存储在UDR中，进而被PCF和SMF信任并执行，导致核心网流量处理行为被恶意篡改。 5. 运维与复制平面风险：攻击者可针对未加密的异地容灾复制链路、缺乏严格控制的数据库管理控制台或未加密的备份文件进行攻击，直接获取完整数据集。 攻击特征： - 攻击面主要集中在标准SBI架构之外的非标准化接口（如配置系统、遗留LDAP、运维平面）。 - 攻击门槛依赖于网络部署的配置缺陷，如弱隔离、粗粒度授权和遗留接口开放。 - 攻击后果严重，可导致用户身份被冒充（窃取认证密钥）、大规模隐私泄露（订阅数据）或核心网流量被恶意重定向（篡改策略和应用数据）。

英文原标题：UDR security in 5G: protecting the Unified Data Repository behind UDM, PCF and NEF

UDR security is the protection of the Unified Data Repository, the 5G core network function that stores subscription data, policy data, exposure data and application data on behalf of other network functions. The UDR is defined in 3GPP TS 23.501 as a storage function accessed by the UDM, the PCF and the NEF through the Nudr service-based interface, and it is the place where long-lived subscriber information actually lives. If the UDM is the brain that decides what a subscriber is allowed to do, the UDR is the memory that the decision relies on. That position makes the UDR one of the highest-value targets in a 5G core, and also one of the least discussed. It rarely appears on architecture slides as a separate box, it is often delivered bundled with the UDM by the same supplier, and it is reached through a mix of standardised and proprietary interfaces. This article explains what the UDR stores, who can talk to it, where its security model is strong and where deployments commonly weaken it, and how operators can test and monitor it. What the UDR does in the 5G core The UDR is the persistent data store of the 5G core, holding the data sets that the UDM, PCF and NEF need to serve subscribers and applications. 3GPP TS 23.501 describes it as the function that supports storage and retrieval of subscription data by the UDM, policy data by the PCF, structured data for exposure, and application data by the NEF, with the detailed service and data models specified in TS 29.504 and TS 29.505. In practice, the UDR plays the role that was split across several systems in earlier generations. Subscription profiles that used to sit in the HSS or the HLR , policy subscriber data that used to sit in a separate subscription profile repository, and application-related data used for traffic influence and packet flow descriptions now converge in one logical repository. That convergence started before 5G: the User Data Convergence architecture in 3GPP TS 23.335 already separated front-end logic from a central data repository reached over the Ud reference point, and many operators run a single converged repository serving 4G front-ends and 5G network functions at the same time. The UDR should not be confused with the UDSF, the Unstructured Data Storage Function. The UDSF is an optional store that network functions such as the AMF or SMF can use to keep their own unstructured context, for example to support stateless designs. The UDR holds structured, standardised data sets that define subscribers and services. Both are storage functions, but the UDR carries the data that determines who a subscriber is and what they can do. What data the UDR holds and why it matters The UDR holds the data that an attacker would need to impersonate, profile or reconfigure a subscriber, which is why its compromise has consequences well beyond a single network function.
