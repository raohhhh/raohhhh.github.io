攻击事件背景 本文探讨了5G核心网中计费功能的安全问题。传统上，计费功能（CHF）被视为后台计费组件，由收入保障团队审计。然而在5G核心网中，CHF是在线策略执行点，其实时决定会话是否继续、分配配额，并与PCF交互进行消费限制决策。由于CHF处于实时会话路径中，且其指令被其他网元执行，因此它应被视为控制平面安全边界的一部分，而不仅是后端系统。 攻击原理 攻击者通过影响计费决策或利用计费链路的信任关系来实施欺诈或破坏。核心原理在于CHF不直接观察流量，而是信任消费者网元（如SMF）报告的使用量和分类。这种信任依赖关系以及会话状态在SMF、UPF和CHF之间的同步窗口，为攻击者提供了可乘之机。 攻击详情 1. 免费乘车：攻击者通过将流量分类为零费率或未跟踪类别，或在未应用计费的窗口期内操作，消耗网络资源而不产生费用。这不仅造成收入流失，还可能导致流量未被详细记录，被用于其他恶意目的。 2. 过度计费：攻击者利用会话释放后地址重用的机制，将第三方流量归因并计费给当前地址持有者或刚释放会话的订阅者，导致用户为未请求或未接收的流量付费。 3. 拒绝服务：攻击者针对CHF发起DoS攻击，迫使网络进入配置的故障模式。如果继续服务，会导致收入流失；如果拒绝服务，则会导致大规模网络中断。可用性攻击是核心网测试中最易复现的发现之一。 4. 漫游计费欺诈：利用漫游计费固有的延迟（如TAP结算和近实时漫游数据交换的4小时窗口），在被发现之前实施高价值欺诈。 攻击特征 - 针对在线计费的配额循环机制进行滥用。 - 利用SMF、UPF和CHF之间会话状态的不一致或同步延迟。 - 针对Nchf等服务化接口（SBA）发起信令层面的DoS攻击或畸形信令攻击，导致网元重启循环。 - 攻击不仅影响计费完整性，还破坏了用于事件响应和取证分析的计费记录日志。

英文原标题：5G charging security: protecting the CHF, Nchf and the charging chain from fraud and denial of service

The Charging Function is usually reviewed as a billing component and audited by a revenue assurance team. That framing is out of date. In a 5G core, the CHF is an online policy enforcement point: it decides in real time whether a session may continue consuming resources, it hands out quota that other network functions act on, and it is consulted by the PCF for spending limit decisions. A network function that can grant or withhold service is a security control, whether or not the organisation chart says so. The direct answer for anyone scoping a 5G core security review: the charging chain deserves the same treatment as any other service based interface, because the realistic threats against it are not exotic. They are abuse of the quota mechanics to consume service that is never billed, abuse of session state to bill traffic a subscriber never sent, and denial of service against the CHF that forces the network into a configured failure mode that is either a revenue hole or an outage. This article walks through what the charging chain does, how each of those abuse classes works, what roaming adds, and which controls actually reduce the exposure. What the Charging Function does in a 5G core 3GPP separates charging into a trigger side and a decision side. Charging Trigger Functions are embedded inside the network functions that observe chargeable events, most importantly the SMF for data connectivity, along with the SMSF for messaging and other function specific cases. The CHF is the central function that receives those events, applies rating and account logic, and returns decisions. The architecture and principles are defined in TS 32.240, the service based interface framework in TS 32.290, and the API itself in TS 32.291, with the data connectivity domain specifics in TS 32.255 and the record formats in TS 32.298. Unlike the earlier split between online and offline charging, the CHF is converged: it handles both. Online charging is the case that carries security weight, because it is interactive. The consumer network function calls the Nchf_ConvergedCharging service with create, update and release operations. It requests service units, the CHF grants a quota, the consumer meters usage against that quota, and when the granted units are nearly exhausted the consumer comes back for more, reporting what it used. Separately, the PCF uses Nchf_SpendingLimitControl to retrieve and subscribe to policy counter status, so that policy decisions such as throttling or blocking can follow a subscriber's spending state. Two things follow from that design. First, charging is in the live session path, not in a nightly batch. Second, the CHF's answers are instructions that other functions obey. Both are reasons to treat it as part of the control plane security perimeter rather than as a back office system, in the same way we argued for the Unified Data Management function and the Network Repository Function .
