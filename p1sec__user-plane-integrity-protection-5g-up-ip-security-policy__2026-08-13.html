英文原标题：User plane integrity protection in 5G: why UP IP is still off in most networks

User plane integrity protection, or UP IP, is the 5G security feature that lets the network integrity-protect subscriber data between the UE and the gNB, not just encrypt it. 3GPP made it mandatory for the gNB to support and optional for the network to use, and that single design decision explains most of what follows: in a large share of deployed 5G standalone networks, UP IP exists in the equipment and is switched off in the policy. The result is a user plane that is confidential but not tamper-evident, which is a materially different security property from the one most people assume they have. This is a deep dive into how UP IP actually works in TS 33.501, why the 64 kbps data rate cap held it back for years, what an attacker can and cannot do when it is off, and how to determine whether it is active in your own network. It assumes familiarity with 5G standalone architecture and the split between control plane and user plane. If you want the surrounding context first, our post on UPF security across N3, N4 and N6 covers the core-side user plane, and 5G explained covers the architecture at a higher level. What user plane integrity protection actually protects UP IP protects the integrity and provides replay protection for user data carried between the UE and the gNB over the radio interface. It does this by computing a message authentication code over each PDCP packet using a key derived from the AS security context, so that a modified or replayed packet is detected and discarded rather than delivered. The important word is "between the UE and the gNB". UP IP is a radio-leg protection. It says nothing about the N3 hop between the gNB and the UPF, which is protected, if it is protected at all, by IPsec as described in TS 33.501 clause 9.3. It says nothing about the N9 hop between UPFs in roaming or in a distributed core, and nothing about what happens to the traffic after the N6 reference point. Operators sometimes describe their user plane as protected because IPsec is deployed on N3; that is a different hop and a different threat model, and it does not compensate for an unprotected radio leg. It is also worth separating integrity from confidentiality clearly, because the two are configured independently. Confidentiality protection of the user plane, applied with 128-NEA1, 128-NEA2 or 128-NEA3, stops an observer reading the payload. Integrity protection stops an active attacker changing it. An attacker positioned on the radio path who can modify ciphertext without detection can still do damage even without being able to read it, because modern traffic patterns are structured and stream ciphers are malleable. Encryption without integrity is a known weakness in protocol design generally, and mobile networks are not exempt from it. Our post on encryption strategies for signalling and user data covers the algorithm set in more detail.
